# Phase 09 / v0.9: Audit History Workflow

## Goal

Make audit report directories a first-class workflow. Users should be able to list reports, find the latest report, and compare the latest two reports without manually copying filenames.

## Scope

- Keep ThreadVault local-first and privacy-first.
- Operate only on existing anonymous JSON audit reports.
- Do not read or emit raw Codex transcripts.
- Do not add UI, MCP, vector search, cloud sync, team features, or external LLM summaries.

## Tasks

- Add `threadvault audit-history list --dir DIR --json`.
- Add `threadvault audit-history latest --dir DIR --json`.
- Add `threadvault audit-history diff-latest --dir DIR --json`.
- Add report discovery in `audit.py`:
  - only match `threadvault-audit-*.json`
  - parse `generated_at`
  - sort by generated time, then path
  - tolerate malformed JSON by recording warnings instead of crashing list/latest
- Add schema contracts:
  - `audit_history_list`
  - `audit_history_latest`
- Add tests for list/latest/diff-latest and malformed report handling.
- Update README, development progress, external review, and research Markdown appendices.

## Acceptance Commands

```powershell
py -3.12 -m pytest
py -3.12 -m ruff check .
threadvault audit-history list --dir <tmp-reports> --json
threadvault audit-history latest --dir <tmp-reports> --json
threadvault audit-history diff-latest --dir <tmp-reports> --json
threadvault schemas show audit_history_list --json
threadvault schemas show audit_history_latest --json
```

## Assumptions

- Reports are JSON files generated by ThreadVault v0.8+.
- Malformed files should not block listing valid reports.
- `diff-latest` requires at least two valid reports and exits non-zero otherwise.
